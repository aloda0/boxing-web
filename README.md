# Сайт и админка «Федерация бокса Югры»

Проект состоит из **сайта для посетителей** и **админки** для редактирования текстов и файлов без программирования. Контент хранится в облаке **Sanity**.

---

## Подключение Sanity (первый раз)

Без реального **Project ID** и **dataset** редактор (Studio) и запросы к контенту не работают. Placeholder-значения в коде не используются — всё задаётся через переменные окружения.

### Где взять Project ID

1. Войдите на [sanity.io/manage](https://sanity.io/manage).
2. Откройте нужный проект (или создайте новый).
3. Перейдите в **Project settings** (шестерёнка) → **API**.
4. Скопируйте **Project ID** — короткая строка из латинских букв, цифр и дефисов.

### Где взять dataset

1. В том же проекте откройте раздел **Datasets** (или в **API** посмотрите используемый датасет).
2. Чаще всего он называется **`production`**. Если создавали другой — укажите его имя **точно**, как в панели.

### Версия API (`apiVersion`)

В файле `.env.example` задано значение по умолчанию **`2024-01-01`** — это дата версии GROQ API. Менять не обязательно, если Sanity не рекомендует другую в [документации по версиям API](https://www.sanity.io/docs/api-versioning).

### Куда вставить значения

1. Скопируйте файл **`.env.example`** в **`.env.local`** в корне проекта (рядом с `package.json`).
2. Заполните строки:
   - **`NEXT_PUBLIC_SANITY_PROJECT_ID`** — ваш Project ID с шага выше;
   - **`NEXT_PUBLIC_SANITY_DATASET`** — имя датасета (часто `production`);
   - при необходимости **`NEXT_PUBLIC_SANITY_API_VERSION`** — оставьте значение из примера, если не знаете, что менять.
3. Перезапустите сервер разработки после сохранения файла.

Переменные с префиксом **`NEXT_PUBLIC_`** попадают в браузер (нужно для Studio внутри Next.js). Дополнительно можно задать **`SANITY_STUDIO_PROJECT_ID`** с тем же Project ID — удобно для команд CLI `sanity`, если они не подхватывают `.env.local` (см. ниже).

### Как запустить Studio

1. Установите зависимости: `npm install` (при конфликте версий: `npm install --legacy-peer-deps`).
2. Запустите приложение: `npm run dev`.
3. Откройте в браузере **[http://localhost:3000/studio](http://localhost:3000/studio)** и войдите под учётной записью, которую пригласили в проект Sanity.

Если при старте видите ошибку про отсутствие **`NEXT_PUBLIC_SANITY_PROJECT_ID`** — проверьте, что `.env.local` лежит в **корне** репозитория и имя переменной без опечаток.

### CORS для локальной разработки

В [sanity.io/manage](https://sanity.io/manage) → ваш проект → **API** → **CORS origins** добавьте `http://localhost:3000` (и при необходимости `http://127.0.0.1:3000`). Иначе Studio в браузере может не подключиться к API.

### Команды CLI `sanity` (опционально)

Инструменты вроде `npx sanity …` по умолчанию читают **`.env`**, а не **`.env.local`**. Варианты: скопировать нужные строки в `.env`, либо выполнять команду так:

`npx dotenv -e .env.local -- sanity …`

(пакет `dotenv-cli` можно установить отдельно: `npm i -D dotenv-cli`).

## Что такое сайт

Это обычная веб-страница в интернете: новости, календарь, документы. Её открывают **зрители и спортсмены** по основному адресу, например `https://ваш-домен.ru`.

---

## Что такое админка

**Админка** — это отдельная страница входа в редактор. Там вы добавляете новости, загружаете PDF и фото. В техническом плане это **Sanity Studio**, встроенная в проект.

После настройки домена админка открывается по адресу вида:

**`https://admin.ваш-домен.ru`**

(поддомен `admin` — тот самый «отдельный адрес»).

На своём компьютере при разработке админка доступна по адресу **`http://localhost:3000/studio`** — это нормально.

---

## Как открыть админку

1. Откройте в браузере ссылку админки (в продакшене — `https://admin.ваш-домен.ru/studio`, при первом заходе с корня `https://admin.ваш-домен.ru` вас перенаправит на `/studio`).
2. Дождитесь экрана входа **Sanity**.

---

## Как войти (авторизация)

Вход **не придумывается в коде**: его выдаёт сам Sanity.

1. Зайдите на [sanity.io/manage](https://www.sanity.io/manage) под учётной записью владельца проекта.
2. Откройте ваш проект → раздел **Members / Участники**.
3. Нажмите **Invite** и введите **email** редактора (коллеги).
4. Человек получит приглашение, создаст пароль или войдёт через Google — как настроите.

**Кто не добавлен в проект Sanity — в админку не попадёт.** Случайный посетитель сайта не сможет менять контент: форма входа есть, а доступ к данным только у приглашённых.

**Сменить способ входа:** это делается в настройках аккаунта на sanity.io (почта, пароль, Google и т.д.), не в файлах сайта.

**Дополнительная защита (по желанию):** на хостинге (например Vercel) можно включить **Password Protection** или ограничение доступа для превью — это отдельно от Sanity. Для большинства организаций достаточно списка участников в Sanity.

## Как добавить новость

1. Войдите в админку.
2. Слева выберите **«Новости»** → **Создать**.
3. Заполните поля (заголовок, дата публикации, фото, текст).
4. Нажмите **Опубликовать**.

Поля названы по-русски, с подсказками.

---

## Как добавить документ (положение, отчёт, вызов)

1. Слева откройте нужный раздел, например **«Положение соревнований»** или **«Отчёты соревнований»**.
2. **Создать** → название, дата, краткое описание, файл (PDF/DOCX можно перетащить в поле).
3. **Опубликовать**.

---

## Как добавить фото

В карточках новостей и спортсменов есть поля для изображения: нажмите на поле или **перетащите файл** с компьютера. После загрузки видно превью.

Если фото не загрузить, на **сайте для посетителей** показывается серая заглушка — сайт не ломается.

---

## Как удалить запись

1. Откройте раздел слева → выберите запись в списке.
2. Откройте запись → в меню действий выберите **Удалить**.
3. Sanity **спросит подтверждение** — без него запись не удалится.

---

## Как изменения появляются на сайте

1. Вы нажимаете **Опубликовать** в админке.
2. Данные сохраняются в облаке Sanity.
3. Сайт для посетителей подгружает их при открытии страницы (с небольшой задержкой кэша, обычно до минуты).

Если что-то не видно — проверьте, что нажато именно **Опубликовать**, а не только «Сохранить черновик».

## Поддомен admin: что сделано в проекте

- Включён **middleware**: если заданы переменные окружения, то  
  - с **основного домена** адрес `/studio` **перенаправляет** на админку;  
  - с **поддомена admin** открывается только редактор (остальные пути ведут в `/studio`).
- Кнопка **«Админка»** в шапке сайта ведёт на `NEXT_PUBLIC_ADMIN_URL` + `/studio`.
- На экране админки **скрыты** шапка и подвал основного сайта — вы видите только редактор.

Подробнее для разработчика: см. файл `src/middleware.ts` и переменные в `.env.example`.

## Как задеплоить сайт и админку на домен

Ниже — схема без глубокой техники. Чаще всего используют **Vercel** (удобно для Next.js).

### 1) Простой вариант (рекомендуем для начала)

**Один и тот же проект** на Vercel обслуживает и сайт, и админку.

1. Зарегистрируйтесь на [vercel.com](https://vercel.com), подключите репозиторий с этим проектом.
2. В настройках проекта → **Environment Variables** добавьте все переменные из `.env.example` (как минимум `NEXT_PUBLIC_SANITY_*`, `NEXT_PUBLIC_SITE_URL`, `ADMIN_HOSTNAME`, `NEXT_PUBLIC_ADMIN_URL`).
3. Выполните деплой (**Deploy**).

**Домены:**

- В **Vercel** → ваш проект → **Settings** → **Domains** добавьте:
  - основной: `ваш-домен.ru` и/или `www.ваш-домен.ru`;
  - админку: `admin.ваш-домен.ru`.

**DNS у регистратора домена** (где купили домен):

| Тип | Имя | Куда указывает |
|-----|-----|----------------|
| A или CNAME | `@` или `www` | то, что покажет Vercel (часто CNAME на `cname.vercel-dns.com`) |
| CNAME | `admin` | то же значение, что Vercel даёт для поддомена |

Точные записи Vercel показывает в интерфейсе после добавления домена — скопируйте их.

**Переменные для продакшена:**

```env
NEXT_PUBLIC_SITE_URL=https://ваш-домен.ru
ADMIN_HOSTNAME=admin.ваш-домен.ru
NEXT_PUBLIC_ADMIN_URL=https://admin.ваш-домен.ru
```

**Sanity — доступ с нового адреса:**

В [sanity.io/manage](https://sanity.io/manage) → ваш проект → **API** → **CORS origins** добавьте:

- `https://ваш-домен.ru`
- `https://admin.ваш-домен.ru`

Иначе редактор может не открыться из браузера.

---

### 2) Надёжный вариант

Тот же стек, но:

- включите **резервное копирование** и контроль доступа в Sanity (план и настройки — на sanity.io);
- на Vercel включайте **автоматические деплои** только из основной ветки;
- по желанию добавьте **защиту паролем** на превью-среды в Vercel.

Для нетехнического редактора **достаточно простого варианта** + приглашений в Sanity.

---

### 3) Альтернатива: админка только на sanity.studio

Команда `npx sanity deploy` выкладывает Studio на адрес вида `ваш-проект.sanity.studio`. Отдельный домен `admin.*` тогда не нужен, но адрес другой, не ваш бренд. Текущий проект ориентирован на **ваш поддомен** через Next.js.

## Установка на компьютер (для разработки)

Нужны [Node.js](https://nodejs.org/) LTS и аккаунт [sanity.io](https://www.sanity.io/).

```bash
npm install
# при конфликте версий:
# npm install --legacy-peer-deps
cp .env.example .env.local
```

Заполните `.env.local` по разделу **«Подключение Sanity»** выше (обязательно **`NEXT_PUBLIC_SANITY_PROJECT_ID`** и при необходимости dataset).

Запуск сайта и админки локально:

```bash
# Рекомендуемый «чистый запуск» (всегда поднимает сайт строго на :3000)
npm run dev:clean
```

- Сайт: [http://localhost:3000](http://localhost:3000)  
- Админка: [http://localhost:3000/studio](http://localhost:3000/studio)  

Переменные `ADMIN_HOSTNAME` и `NEXT_PUBLIC_ADMIN_URL` **не задавайте** на своём ПК — поддомен тогда не используется.

### Если сайт завис или открылся на 3001

Такое бывает, если:
- порт **3000** занят старым процессом;
- кэш **`.next`** повреждён (после падения/остановки).

Используйте одну команду:

```bash
npm run dev:clean
```

Она:
- завершает процесс, занимающий **порт 3000**;
- удаляет папку **`.next`**;
- запускает Next.js строго на **`http://localhost:3000`**.

## Кратко: что выбрать нетехническому пользователю

| Цель | Рекомендация |
|------|----------------|
| Быстро начать | Vercel + один проект + два домена (основной и admin) + переменные из README |
| Спокойствие за данные | То же + только доверенные люди в Members в Sanity |
| Свой адрес админки | Поддомен `admin` и переменные `ADMIN_HOSTNAME` / `NEXT_PUBLIC_ADMIN_URL` |

Если нужна помощь с DNS, обычно её даёт тот, кто покупал домен, или поддержка хостинга.
